# 医療情報の安全管理ガイドラインへの対応状況

対象とするガイドライン（最新版を必ず確認すること）
- 厚生労働省「医療情報システムの安全管理に関するガイドライン」（第6.0版）
- 経済産業省・総務省「医療情報を取り扱う情報システム・サービスの提供事業者における安全管理ガイドライン」

レセ番は、医療機関から委託を受けて医療情報を扱う「サービス提供事業者」にあたります。
下の表の「システム」はこのリポジトリで実装済みのもの、「運用」は運営者が体制・文書として整える必要があるものです。

## 技術的対策（システム側）

| 項目 | 対応 | 実装 |
|---|---|---|
| 取り扱う情報の最小化 | 済 | 氏名・カナ氏名・保険証の記号番号・生年月日は取込時に破棄（`src/lib/uke/parser.ts`）。年齢と匿名キーのみ保持 |
| 保存時の暗号化 | 済 | レセプト本体を AES-256-GCM で暗号化（医院ID・月を認証データに含め、取り違えを防止）。DB自体も RDS の保存時暗号化 |
| 通信の暗号化 | 構築時 | ALB で HTTPS のみ・HSTS。DB 接続は TLS |
| 国内でのデータ保管・処理 | 構築時 | AWS 東京リージョン。AI は Bedrock 東京／Vertex 東京を選択可能 |
| 利用者の識別・認証 | 済 | 個人ごとのアカウント、12文字以上のパスワード、scrypt でハッシュ化 |
| 2要素認証 | 済 | TOTP。運営者は必須、医院ごとに必須化を選択可能 |
| 不正ログイン対策 | 済 | 5回失敗で15分ロック、IP単位の試行制限 |
| セッション管理 | 済 | HttpOnly・Secure・SameSite Cookie、無操作60分で自動ログアウト、最長12時間 |
| アクセス権限 | 済 | 運営者／管理者／スタッフの3区分。運営者は医院のレセプト・結果を閲覧不可 |
| 医療機関間のデータ分離 | 済 | すべての読み書きを医院IDで絞り込み（テスト `tests/tenant.test.ts`） |
| アクセスログ | 済 | ログイン・失敗・レポート閲覧・CSV出力・AI利用・設定変更などを記録し、医院管理者が閲覧・CSV出力可能 |
| AIへの情報提供 | 済 | 患者を特定できる情報（カルテ番号含む）を送らない。番号らしき文字列も伏せる（`src/lib/ai/mask.ts`） |
| 保存期間と削除 | 済 | レセプトは医院ごとに設定した期間（初期13か月）、結果は36か月で自動削除。医院管理者による全削除 |
| Webの一般的な脆弱性対策 | 済 | CSRF（Origin 検査）、CSP・X-Frame-Options 等のヘッダー、CSV の数式インジェクション対策、アップロードサイズ制限 |
| 依存パッケージの脆弱性 | 済 | CI で `npm audit`（high 以上で失敗） |

## 運用・体制（運営者が整えるもの）

| 項目 | 必要なもの |
|---|---|
| 契約 | 医療機関との業務委託契約（個人情報の取扱い、再委託先の明示、事故時の報告、契約終了時の返却・消去） |
| 情報開示 | サービス仕様適合開示書（JAHIS/JIRA の SDS 様式）、責任分界の説明資料 |
| 規程類 | 情報セキュリティ基本方針、運用管理規程、アクセス権管理手順、障害・事故対応手順、BCP |
| 人的対策 | 従業者の守秘義務契約、年1回以上の教育 |
| 第三者評価 | 脆弱性診断（リリース前と年1回）、可能なら ISMS（ISO/IEC 27001）・ISMS クラウドセキュリティ（27017）・プライバシーマーク |
| 監査 | 操作ログ・AWS の CloudTrail の定期確認と記録 |
| バックアップ | 復旧手順書と年1回以上の復旧訓練 |
| 鍵管理 | `DATA_ENCRYPTION_KEY` の保管・アクセス権限・紛失時の手順 |
| 事故対応 | 漏えい等が起きた場合の医療機関・個人情報保護委員会への報告手順 |
