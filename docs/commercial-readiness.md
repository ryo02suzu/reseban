# 商用化までのチェックリスト

「システムとして出来ていること」と「人・会社として整える必要があること」を分けて書いています。
**ソフトウェアはこのリポジトリで一通り動く状態**ですが、医療情報を預かる有償サービスとして出すには、下の「未了」を埋める必要があります。

## 1. 出来ていること（このリポジトリで確認済み）

| 分野 | 内容 | 確認方法 |

## 2. 未了（出す前に必ずやること）

### 2-1. 中身の正しさ（いちばん大事）

- [ ] **実物のレセ電で検証**：実家（協力医院）の当月＋過去6か月の `RECEIPTC.UKE` を取り込み、読めない行・警告が出ないか確認する。今は仕様書どおりに作ったサンプルでしか試していない。
- [ ] **指摘の答え合わせ**：同じ月の実際の返戻・査定と、レセ番の指摘を突き合わせる。「当たった／外れた／誤検知」を数え、誤検知の多いチェックは直すか無効にする。
- [ ] **上位30ルール**：実家の過去1年分の返戻・査定を実績CSVにして取り込み、多い順に並べる。公式マスターで拾えない理由（病名・前提・独自の組み合わせ）は共通ルールとして追加する（今の独自ルールは8本の“たたき台”）。
- [ ] 独自ルールの根拠（告示・通知・疑義解釈の該当箇所）を歯科医師・請求担当者に確認してもらう。
- [ ] 算定漏れの金額（届出あり未算定）は「取れたかもしれない点数」の目安であることを画面・規約で明示済みか確認する。

### 2-2. 法務・契約

- [ ] **利用規約・プライバシーポリシー**：`/legal/terms`・`/legal/privacy` はたたき台（［ ］の穴埋めと「要弁護士確認」の表示あり）。医療分野に詳しい弁護士に見てもらい、確定したら `TERMS_VERSION` を上げる（全員に再同意を求める画面が出る）。
- [ ] 医療機関との**業務委託契約書**（個人情報の取扱い、再委託先＝AWS・AIの提供元の明示、事故時の報告、契約終了時の返却・消去、損害賠償の上限）。
- [ ] **SLA**（稼働率の目標、問い合わせの受付時間、計画停止の連絡方法）。
- [ ] 「判定は参考情報で、請求の最終判断は医療機関」という責任分界の説明資料。
- [ ] 特定商取引法に基づく表記（Web で申し込みを受ける場合）。

### 2-3. セキュリティ・第三者評価

- [ ] リリース前の**脆弱性診断**（外部業者）。以後年1回。
- [ ] **サービス仕様適合開示書（SDS）** の作成（医療機関から求められることが多い）。
- [ ] 規程類：情報セキュリティ基本方針、運用管理規程、事故対応手順、BCP（[ガイドライン対応表](security-guideline.md) の「運用」欄）。
- [ ] 可能なら ISMS（ISO/IEC 27001・27017）かプライバシーマーク。
- [ ] 暗号化キー（`DATA_ENCRYPTION_KEY`）の保管手順と、紛失・漏えい時の対応。今は単一鍵で、**鍵の入れ替え（ローテーション）機能はまだない**。

### 2-4. 本番環境

- [ ] [本番構築](deploy-aws.md) に沿って AWS 東京に構築（RDS Multi-AZ、ECS Fargate、WAF、Secrets Manager、監視）。
- [ ] **Bedrock 東京での AI 接続テスト**：運営コンソールの「接続テスト」→ レポートで「根拠をAIで説明」「算定漏れ候補」、ルールで「AIでルール案」を実際に動かす（このリポジトリでは実機のAIには繋いでいない）。
- [ ] バックアップからの復旧を一度やってみる。
- [ ] 独自ドメインと証明書、問い合わせ窓口のメールアドレス。

### 2-5. 事業まわり（システム外、または今後の追加開発）

- [ ] **課金**：今は運営者が医院を「停止」できるだけで、決済・請求書の機能はない。当面は請求書払いで運用し、必要になったら決済サービスと連携する。
- [ ] **メール送信**：招待・再設定リンクは画面に表示して手渡しする方式（電話で本人確認してから渡す）。メールで送る場合は送信サービス（Amazon SES 東京など）の追加が必要。
- [ ] サポート体制（問い合わせ窓口、マスター更新の月次作業、改定時の対応）。
- [ ] 導入マニュアル（医院向け、画面キャプチャ付き）。

## 3. 既知の制約

- 対象は**歯科の外来・訪問のレセ電**。医科・調剤・入院は対象外（入院レセプトは取り込むが入院特有のチェックはない）。
- 回数・間隔は、取り込んだ期間（最長で当月＋過去6か月）の中でしか数えられない。年1回などの制限は、取り込んでいない月の算定を見落とす可能性がある。
- 歯式はレセ電の傷病名（HS）とコメント（CO）にしか載らないため、部位のチェックは「病名の付いている歯」と「コメントの歯式」から判断している。
- AIの説明・提案は誤りを含む可能性がある。合否には使っていないが、画面で「AIの提案」と明示している。
