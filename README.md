# レセ番（レセプトの番人）

歯科のレセ電データ（当月＋過去6ヶ月）から、**返戻リスク○件／査定リスク○円／算定漏れ○円** と、1件ずつの理由・根拠・直し方を出す、医院向けの Web サービスです（複数医院対応）。

- 判定は**ルールエンジン**だけで行います。AIは合否を決めません。
- AIの仕事は3つだけです：根拠の説明、算定漏れ候補の提案、改定・疑義解釈からのルール案づくり（採用は運営者が決める）。
- 氏名・カナ氏名・保険証の記号番号・生年月日は**取り込んだ瞬間に捨て**、保存もAI送信もしません。レセプトは暗号化して保存します。

商用化の進み具合と残りの作業は **[docs/commercial-readiness.md](docs/commercial-readiness.md)** にまとめています。

**デモ**：https://reseban-demo.vercel.app （架空データのみ。ログイン画面にデモ用アカウントを表示しています）

## 画面

| 利用者 | 画面 |
|---|---|
| 医院（管理者・スタッフ） | チェック（取込）／紙レセプト入力／レポート／返戻・査定の記録（答え合わせ）／ルール／設定※／メンバー※／操作ログ※（※は管理者のみ） |
| 運営者 | 医院／マスター／共通ルール（AIルール案の採否）／操作ログ |

## チェックの6分類

| 種類 | 元になるもの | 例 |
|---|---|---|
| 回数・間隔オーバー | 支払基金マスター（算定回数限度） | 歯科疾患管理料が同月2回 |
| 併算定不可 | 支払基金マスター（併算定背反） | 同日の初診料と再診料 |
| 前提の検査・管理なし | 共通ルール | 歯周病検査なしのSRP |
| 病名・部位のズレ | 共通ルール＋マスター（年齢制限） | 歯髄炎の病名がない歯の抜髄 |
| 必須コメント漏れ | 支払基金マスター（コメント関連テーブル） | 訪問診療の実施時刻 |
| 施設基準のズレ | 支払基金マスター＋共通ルール | 届出なしの算定／届出ありなのに加算なし |

公式マスター由来のチェックは、マスターを取り込み直すだけで改定に追従します。

## ローカルで動かす

Node.js 22 が必要です。DB を用意しなくても、組み込みの PostgreSQL 互換 DB（PGlite、`./data/pglite`）で動きます。

```bash
npm install
npm run create-operator -- you@example.com   # 運営者の招待リンクを表示（DB の作成もここで行う）
npm run dev                                  # http://localhost:3000
```

開発用 DB（PGlite）は1つのプロセスからしか開けないため、`create-operator` は `npm run dev` を止めた状態で実行してください。

1. 表示された招待リンクで運営者を登録し、2段階認証を設定する。
2. 運営コンソール「マスター」で支払基金の基本マスター（9ファイル、ZIPのままで可）を取り込む。
3. 「医院」で医院を追加し、医院の管理者の招待リンクを発行する。
4. 医院の管理者でログインし、「設定」で施設基準の届出にチェック → 「チェック」でレセ電を取り込む。「サンプルデータで試す」でも全体を確認できます。

### 院内のパソコンだけで使う（インターネットに公開しない）

Node.js 22 を入れたパソコンで：

```bash
npm install
npm run local -- you@example.com   # 初回だけメールアドレスを付ける（最初の管理者の招待リンクが出る）
npm run local                      # 2回目以降
```

`http://127.0.0.1:3000` をそのパソコンのブラウザで開きます（他のパソコンからは開けません）。データと暗号化キーは `./data` に保存されるので、フォルダごとバックアップしてください。

### 本番と同じ構成で試す

Docker＋PostgreSQL 16：

```bash
DATA_ENCRYPTION_KEY=$(openssl rand -base64 32) docker compose up --build   # http://localhost:3000
docker compose exec app node scripts/create-operator.mjs you@example.com
```

### 取り込めるもの

- **レセ電（RECEIPTS.UKE）**：当月＋過去6ヶ月分をまとめて選べます。社保（支払基金）と国保（国保連）で分かれたファイル、マルチボリュームにも対応し、月ごと・機関ごとに自動で振り分けます。
- **紙レセプト**：「紙レセプト入力」で1枚ずつ入力（氏名・保険証番号の欄はありません）。部位は「右下6」「46」「上顎」、算定日は「3,10」のように入れます。「この1枚をチェック」でその場で判定、「この月をまとめてチェック」でレポートになります。
- **返戻・査定の記録**：増減点連絡書などを見ながら1件ずつ記録するか、CSVで取り込みます。ルールの優先順位づけと、**答え合わせ**（実際の返戻・査定をレセ番が指摘できていたか・的中率）に使います。

```
年月,区分,項目名,事由,点数,カルテ番号（任意）
202501,査定,歯科疾患管理料,回数超過,100,1234
202503,返戻,歯科訪問診療1,記載不備,1100
```

## 環境変数

全項目は [.env.example](.env.example) を参照してください。本番で必須なのは次の3つです。

| 変数 | 内容 |
|---|---|
| `DATABASE_URL` | PostgreSQL の接続先（未設定なら開発用 PGlite） |
| `DATA_ENCRYPTION_KEY` | レセプト暗号化キー（`openssl rand -base64 32`）。本番で未設定なら取込を拒否します。**紛失すると復号できません** |
| `APP_URL` | 公開URL（招待リンクに使う） |

AI を使う場合は `AI_PROVIDER=bedrock`（Amazon Bedrock 東京、推奨）か `vertex`（Google Cloud 東京）を設定します。`anthropic` は国内リージョンを指定できないため検証用です。

## 開発

```bash
npm test            # パーサー・マスター・ルールエンジン・認証・暗号化・医院間分離のテスト
npm run lint
npm run typecheck
npm run build
npm run db:generate # src/lib/db/schema.ts を変えたらマイグレーションを作る（起動時に自動適用）
```

| 場所 | 中身 |
|---|---|
| `src/lib/uke` | レセ電パーサー（列位置は `layout.ts` にだけ書いてある） |
| `src/lib/paper` | 紙レセプトの入力をレセ電と同じ形にする |
| `src/lib/master` | 支払基金マスターの読み込みと索引 |
| `src/lib/rules` | ルールエンジン（公式テーブル `official.ts`、共通ルール `builtin.ts`、答え合わせ `outcome.ts`） |
| `src/lib/ai` | AI（説明・算定漏れ候補・ルール案）と送信前のマスク |
| `src/lib/db`・`src/lib/repo` | DB スキーマと、医院IDで絞り込んだ読み書き |
| `src/lib/security`・`src/lib/auth.ts` | パスワード・2段階認証・暗号化・セッション |
| `src/app` | 画面と API（`(clinic)` 医院／`(admin)` 運営者／`(public)` ログイン・規約） |
| `tests/fixtures/ssk` | 支払基金の公開マスターの抜粋（サンプルデータ用、`npm run build:demo-master`） |

実在の患者データは、テストにもサンプルにも含めません。`./data` はコミットしないでください（`.gitignore` 済み）。

## Vercel でデモを動かす

DB を設定していない Vercel のデプロイは、自動で**デモモード**になります（`src/lib/demo/mode.ts`）。メモリ上の DB に架空の医院・アカウント・サンプル結果を作り、実データの取込・保存は受け付けません。本番は Vercel ではなく [AWS 東京](docs/deploy-aws.md)（または院内PC）で動かしてください。
