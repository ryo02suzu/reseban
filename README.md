# レセ番（レセプトの番人）

歯科のレセ電データ（当月＋過去6ヶ月）から、**返戻リスク○件／査定リスク○円／算定漏れ○円** と、1件ずつの理由・根拠・直し方を出すWebアプリです。

- 判定は**ルールエンジン**だけで行います。AIは合否を決めません。
- AIの仕事は3つだけです：根拠の説明、算定漏れ候補の提案、改定文書からのルール案づくり（採用は人が決める）。
- 氏名・保険証番号・生年月日は**取り込んだ瞬間に捨て**、保存もAI送信もしません。

## 使い方

```bash
npm install
cp .env.example .env.local   # 必要なら AI・ログインを設定
npm run dev                  # http://localhost:3000
```

1. **設定** → 支払基金の「歯科診療行為マスター」を取り込む。施設基準の届出にチェックを入れる。
2. **チェック（取込）** → 当月の `RECEIPTC.UKE` と過去6ヶ月分を選んで「チェック開始」。一度入れた月は保存され、次回からは不要です。
3. **レポート** → 指摘を「対応済み」「問題なし」にしていく。CSV出力・印刷ができます。
4. **ルール** → 過去1年の返戻・査定CSVを取り込み、「この順でルールを並べ替える」。

「サンプルデータで試す」を押すと、架空のデータで全機能を確認できます。

### 返戻・査定の実績CSV

```
年月,区分,項目名,事由,点数
202501,査定,歯科疾患管理料,回数超過,100
202503,返戻,歯科訪問診療1,記載不備,1100
```

## チェックの6分類

| 種類 | 例 |
|---|---|
| 回数・間隔オーバー | 歯科疾患管理料が同月2回 |
| 併算定不可 | 同日の初診料と再診料 |
| 前提の検査・管理なし | 歯周病検査なしのSRP |
| 病名・部位のズレ | 歯髄炎の病名がない歯の抜髄 |
| 必須コメント漏れ | 訪問診療の実施時刻 |
| 施設基準のズレ | 届出なしのCAD/CAM冠／届出ありなのに加算なし |

## 本番前に必ず確認すること（要確認）

このリポジトリには実物のレセ電・マスターが入っていないため、以下は**公式資料との照合が必要**です。

1. **レセ電の列位置**：`src/lib/uke/layout.ts`。「記録条件仕様（歯科用）令和8年6月版」と照合してください。列番号はこのファイルにだけ書いてあります。
2. **診療行為と部位の結びつけ**：今は「直前の傷病名部位（HS）の歯式を、後続の診療行為に引き継ぐ」扱いです（`parser.ts`）。
3. **マスターの列**：`src/lib/master/parse.ts`。コード・名称は自動で探しますが、点数列（12列目）は要確認です。取込後に表示される例で目視確認してください。
4. **初期ルール**：`src/lib/rules/builtin.ts` は“たたき台”です。算定要件は令和8年度改定の告示・通知・疑義解釈で確認し、実家の返戻・査定の上位30件に合わせて作り直してください。
5. **施設基準の名称**：`src/lib/facility.ts` は令和6年度改定時点の名称です。

## AIとデータの置き場所

- `AI_PROVIDER=bedrock`（AWS東京）か `vertex`（Google Cloud東京）を推奨します。`anthropic` は国内リージョンを指定できないため検証用です。
- AIに渡すのは項目名・病名・部位・指摘の理由だけです。カルテ番号・レセプト番号も渡しません（`src/lib/ai/tasks.ts`）。念のため番号らしきものは伏せています（`src/lib/ai/mask.ts`）。
- データは `./data` にJSONで保存します（`.gitignore` 済み）。院外に置くときは国内リージョンの暗号化ディスクを使い、`BASIC_AUTH_*` を設定してHTTPSで公開してください。医療情報システムの安全管理ガイドライン（厚労省）と、事業者向けガイドライン（経産省・総務省）に沿った運用は別途必要です。
